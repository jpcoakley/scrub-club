# scrubclubhockeyteam.com (Scrub Club)

Beer-league hockey team site. Static SPA, design tokens inline in index.html (burgundy/oatmeal, Futura/Archivo/Big Shoulders). The display font is **Futura Bold** (JP's pick, Sep 17, 2026): the stack is `"Futura-Bold","Futura","Jost"`, so iPhones and Macs use their built-in Futura and everything else gets Jost 700 from Google Fonts, the closest free clone. Futura itself cannot be shipped (no web licence). Graduate was the display font before that day; its zero has a dot in it, which JP will not have (Rokkitt was live for an hour in between). Same stack in privacy/index.html and beer-review.html.

## Deploy

GitHub Pages from `jpcoakley/scrub-club`. **Pushing to main is what deploys.**

Local preview: Google Drive paths are blocked for the preview server, so serve a copy from the session scratchpad.

1. `rsync -a --delete --exclude .git ./ <scratchpad>/site/` (re-run after every edit; run `sync-routes.sh` first if index.html changed).
2. `python3 -m http.server --directory ...` fails at startup (`PermissionError` from `os.getcwd()`, because the launch cwd is on Drive). Write `<scratchpad>/serve.py` instead, which changes directory before serving:
   ```python
   import os, sys, http.server, functools
   d=sys.argv[1]; os.chdir(d)
   http.server.ThreadingHTTPServer(("127.0.0.1",8471), functools.partial(http.server.SimpleHTTPRequestHandler, directory=d)).serve_forever()
   ```
3. The launch entry is `scrub-club-site` in `Hockey/Claude/.claude/launch.json` (the parent folder, not this repo): `"runtimeExecutable": "python3"`, `"runtimeArgs": ["<scratchpad>/serve.py", "<scratchpad>/site"]`, `"port": 8471`. The scratchpad path changes every session, so update both args, then `preview_start` with that name.

The console shows harmless 404s for `/team/stats.json`; the page falls back to `/stats.json`.

- The Swag tab is a hand-maintained gallery of `.swag-card`s linking to the Printful Quick Store (https://scrubclubhockeyteam.printful.me). Products are created in Printful, then added here by hand.
- Roster, dues, season statuses and the game log (beer duty, awards, scores) live in the **Scrub Club Airtable base** (`appCz1cVjdb97VIH3`, in JP's Scrub Club workspace: `Roster` `tblFtcC4EtRuKsONI`, `Games` `tblmugGYBH1Y3bsHa`), not in this repo. Moved off the Scrub Club Roster Google Sheet on Sep 17, 2026; the sheet is frozen history and nothing reads it. Dues collection runs through the `collect-dues` skill; the season status fields are sacred (In, Paid, Half, Goalie count as on the team; Sub, Unsure, Out don't; `<season> Fee` and `<season> Paid` currency fields feed the `Money Owed` formula).
- Schedule renders `schedule.json` and Team renders `stats.json` (Stats was folded into Team; `/stats/` still routes there), weekly GameSheet snapshots taken by the `scrub-club-schedule-refresh` scheduled task. GameSheet sits behind a Cloudflare bot check: curl gets 403, only the in-app Browser works, and the "Verify you are human" box is never clicked (it clears on its own with the tab fronted). Team pages: `/seasons/<season>/teams/<team>/team-stats` renders two tables; `scripts/gamesheet-stats.js` turns them into a season's stats.json entry.
- GameSheet JSON API: once a gamesheetstats.com tab has cleared the bot check, the page can fetch same-origin JSON through `javascript_tool` (top-level `await` works). Use it for games instead of reading the rendered games list, which is virtualized and renders as a table (not `.bracket-card` cards) at wide viewports.
  - `/api/leagues/1147759/seasons`: the league's active seasons with their ids (league 1147759 is Ice Pack Hockey).
  - `/api/unified-games/<season>?order=asc&limit=300&offset=0`: every game in the season. Each item in `data` has number, date ("Sep 10, 2026"), time, location ("Rink 2"), status ("final" or "scheduled"), gameType, and visitor/home objects with title and goals. `meta.total` is the game count. The payload is large, so map it to compact fields inside the javascript call.
  - Our team titles are schedule.json's `teamAliases`; Winter 2026-27 is season 15842, team 553772 ("Scrub Club (WHT)").
- stats.json names are GameSheet's short form ("D. Sanders"). index.html joins them to the Roster by last name, initial and jersey; `GS_ALIASES` pins the ones that can't be settled. The Beer column counts that season's runs in the Games table.
- Scrub Stats (was Beer Stats; Team page, all-time): rank, player, then Beer runs, 3rd Beer and Scrub Daddy, each a count over the date it last happened (`renderBeerStats`, from `beerLog` and `awardLog` in `loadBeer`). Sorted by runs, then awards, then longest since the last run; a player with awards but no runs still appears. Phones stack the three under the name with labels.
- Game awards: the Games table's `Third Beer` and `Scrub Daddy` fields (links to Roster) are the list's 3rd Beer and Scrub Daddy columns (Beer, 3rd Beer, Scrub Daddy on desktop; labelled lines under the opponent on phones). A played game in a season with a team gets an Assign button per empty award; the pop-up is the Beer Man one with `kind` third or daddy, and the Worker's `/assign` takes `award:"third"|"daddy"` (today or earlier, empty field only) plus `seasonKey` so a date only matches that season's game. The next-game card is a wide band above the list from 900px (not beside it: three duty columns need the width).
- Schedule Beer Man assignments: the Assign button in an empty Beer Man cell opens a pick list of that season's team (statuses In, Paid, Half, Goalie in the season's status field; `ON_TEAM` in index.html and worker.js, keep them in step) and posts `{date, name, season, seasonHeader, seasonKey, award?}` to the Worker's `/assign` (`BEER_REQUEST_URL` in index.html; empty hides the buttons). The Worker re-checks team status against the Roster field named `seasonHeader`, takes beer only for unplayed games today or later and awards only for games today or earlier, refuses a field that already holds a name (`taken`), and writes a link to the player on the Games row for that date, creating the row (Date, Season, Type, Opponent) if there isn't one, under a KV lock `lock:assign:<ymd>`. Changing or clearing a name is done by hand in Airtable. `sendBeerRequest` sends up to three times until it gets a refusal with a reason or a name, and treats "already has it" naming the very player it sent as a save from a lost reply. `apps-script/beer-request.gs`, the sheet-era web app, was retired with the move (its deployment in Google can be deleted).
- Worker caches (no cron any more): `cache:schema` (the Roster's `USA Hockey, <yyyy>` and `<Season>, <yy>` field names, a day), `cache:roster2` (sign-in's email map) and `cache:public` (the site's roster grid and game log) live in KV with no expiry. A copy older than four hours is served as is and refreshed behind the response; a site write (`/assign`, `/usah`) refreshes right away; `?fresh=1` waits for a re-read (also of the field list) at most once a minute; an unknown sign-in email re-reads the roster at most once a minute. **Airtable's free plan allows about 1,000 API calls a month per workspace**, and a refresh is two calls (three with the field list), so keep the refresh policy stingy. Airtable calls time out at 10 s; a failed refresh serves the last copy, and only a cold cache with Airtable down is an error.
- **The base is private and the Worker holds the only token**: `AIRTABLE_TOKEN` (`cd worker && npx wrangler secret put AIRTABLE_TOKEN`; a personal access token with `data.records:read`, `data.records:write`, `schema.bases:read`, limited to this base; never in the repo). The site loads `TEAM_DATA_URL` (api.scrubclubhockeyteam.com/public), which the Worker builds from Airtable **in the old sheet's grid shape** so index.html's column lookups never changed: `rosterGrid` puts the header on row 7 with the USA Hockey years ending at column J, Jersey # at L, First/Last at O/P and the season statuses from U (only those columns are filled; no emails, phones, Venmo or dues), and `scheduleGrid` is the old Schedule tab's 12 columns with dates as "Sep 10, 2026" and linked players as names. A new season = JP adds a `<Season>, <yy>` single-select field on Roster (plus `<season> Fee` / `<season> Paid` and the Money Owed formula); a new registration year = a `USA Hockey, <yyyy>` text field. Both are found by name (`SEASON_RE`, `USAH_RE` in worker.js) within a day, or right away after `/public?fresh=1`.
- Privacy policy: `privacy/index.html`, a standalone page (not an SPA route, so sync-routes leaves it alone), linked from the footer. Update it and its date whenever what the site stores or who it shares with changes.
- Team tables sort by any column header (`teamSort`, `statsTable`): first click uses the column's natural order (numbers high to low; #, name, USA Hockey and GAA low to high), a second click flips it; rows with no GameSheet line sort last.
- **USA Hockey numbers** (since Sep 17, 2026): a signed-in player's own Team row shows Add or Edit (`usahCell`, `nameCell`'s phone line, the `#usah-dlg` pop-up). The site POSTs `/usah {value}` to the Worker, which checks the session and writes the Roster row's newest `USA Hockey, <year>` field (the same one the site reads via `COL_USAH`). **Each winter JP adds the next year's field** and players fill it in; the Team page has its own Signed in / Sign in bar (`#team-bar`) for this. Format: 4 to 24 letters and digits, spaces and hyphens stripped; an empty value clears the field.
- **The puck** (since Sep 17, 2026, JP's design): the next-game card's In/Out control is a CSS 3D hockey puck (`puckEl`, `puckDraw`, `puckTween`, `puckNearest`, `puckStatus`, constants in `PUCK`: 150 px across, 50 thick, tilted 30 degrees, 32 wall strips), IN on one face and OUT on the other, seen from just above. Tap it or flick it sideways and it rolls over (answer flips); a quick upward flick (mouse) or a press-and-hold (450 ms, any pointer) stands it on its edge, which is no answer (`answer ""`); standing, a flick left lands In and right lands Out, and a tap drops it back to the side it came from. `touch-action: pan-y`, so a thumb scroll that starts on the puck scrolls the page (the browser cancels the pointer) instead of changing an answer; a slow vertical drag settles back. Keyboard: Enter/Space turn it over, Left In, Right Out, Up or Backspace clear; the stage is `role=button` with the state in its name, the visuals are aria-hidden, a bare click (assistive tech) acts like Enter, focus survives the redraw, and `#sched-live` announces the new status. Its pose lives per game in `puckState` because `renderSchedule` rebuilds the DOM on every change; the roll is a requestAnimationFrame tween that draws onto the latest element, so a redraw mid-roll doesn't jump, and the pose is re-aimed to whatever `mine` says after any redraw (a failed save rolls it back, a teammate answering for you rolls it). Input is ignored while it is rolling. Signed out, it sits on its edge with "Tap the puck to answer." and a flick opens the sign-in with the answer pending. Status line under it: "See you Tuesday." / nothing when Out (the puck says it) / "No answer yet.". Geometry and lighting are derived in the comment above `PUCK`; the design canvases are "Scrub Club In/Out redesign" and "Realistic puck" in JP's artifacts. The rows' You column is the same puck at 44 px (`PUCK_MINI`, `puckEl(..., {mini:true})`), sharing the game's `puckState` with the card so the two roll together (`st.nodes`, `puckDrawAll`); a tap on it does not open the row's names list. `ioToggle` remains for the opened names row's You toggle and the teammate picker.
- Team letters: `CAPTAINS` (C: David Sanders) and `ALTERNATES` (A: Adam Davis; Fred Small from Winter 2026-27) in index.html's CONFIG, as `{name, from}` where `from` is the first SEASONS key the letter applies to (omit for every season). Names must match the Roster's Name field (First + Last) exactly.
- **In/Out** (Schedule tab, since Sep 17, 2026; layout "next game first" since Sep 17 too): a single upcoming season shows its next game as a burgundy card (`heroCard`: **the puck**, who is in and out, how many haven't said, a teammate picker when signed in, the Beer Man with Assign) beside the list on wide screens (`.sched-c.has-hero`, 1180px and up) and above it otherwise. Each upcoming row's You column shows your answer (In ✓ / Out) or an Answer button; tapping a row or that button opens the names row (`rsvpNamesRow`: your In/Out toggle, In, Out, "No answer" = that season's team from the Roster; no teammate picker there, that is only on the next-game card, JP's call Sep 17, 2026). All Seasons and past seasons have no card. Backed by the Cloudflare Worker in `worker/` at **api.scrubclubhockeyteam.com** (`RSVP_API` in index.html; empty hides the column). Deploy it with `cd worker && npx wrangler deploy` (separate from the GitHub Pages site). Sign-in is a six-digit code emailed to the address in the Roster's **Email** field (plus `EXTRA_EMAILS` in worker.js for JP); the Roster is the allowlist, and clearing an email signs that person out the next time the roster copy refreshes (up to four hours). Codes go out from `MAIL_FROM` in worker/wrangler.toml, on the account's verified sending domain (familytree.jpcoakley.com); to send from scrubclubhockeyteam.com, add that domain under Email Service in the Cloudflare dashboard and change the var. Answers are KV keys `rsvp:<season key>:<yyyy-mm-dd>:<name>` with the answer in metadata, so a season reads back in one list call; a fresh write can take up to a minute to show in that list, which is why the page updates itself from the POST reply. The session is a KV key named by a random token; the page keeps the token in localStorage (`scrub.session`) and sends it as a Bearer header, and the Worker also sets it as an HttpOnly cookie on scrubclubhockeyteam.com (sent with `credentials:"include"`), so Safari clearing site storage after a week away doesn't sign anyone out. /me renews a session weekly (not per visit: KV reads can be a minute stale and a per-visit renewal resurrected a just-deleted session in testing). The page ends a session only on a 401. There is no per-address cap on codes (JP hit the old one); only a per-network cap of 60 an hour. Only unplayed games on schedule.json that are today or later (Eastern) accept answers. Anyone signed in can answer for a teammate (the "Someone else" picker under a game's names lists everyone on the Roster); such an answer is stored and shown like the player's own (JP dropped the "(via JP)" tag on Sep 17, 2026; older records may still carry a `by` field the site ignores). JP's rules: no reminder emails, and no explanatory line in the signed-out bar (just "Sign in"). Inspect answers: `npx wrangler kv key list --namespace-id 1ed90cad12c94c33917afab4fd90716f --prefix rsvp: --remote`.
